# SmartAPI (Angel One) Full Documentation Reference

Root API endpoint: `https://apiconnect.angelone.in`
Login (publisher) endpoint: `https://smartapi.angelone.in/publisher-login?api_key=xxx&redirect_url=yyy&state=statevariable`

## Introduction

SmartAPI is a set of REST-like HTTP APIs to build a trading algo: execute orders in real time (equities, commodities), manage user portfolios, stream live market data over WebSockets, and more. All input/output is JSON. Standard HTTP codes used. CORS-enabled (callable directly from browsers).

## Response Structure

All POST params are `application/json`; responses are always JSON.

Successful response:
```json
{
  "status": true,
  "message": "SUCCESS",
  "errorcode": "",
  "data": {}
}
```

Failed response:
```json
{
  "status": "false",
  "message": "Login Id or password is invalid",
  "errorcode": "AB1007",
  "data": "null"
}
```

`status=false` on error; `errorcode` has the code; `message` has textual description.

### Required Headers (every POST, except loginByPassword needs no Authorization)

| Header | Value | Description |
|---|---|---|
| Content-Type | application/json | application/json |
| X-MACAddress | MAC_ADDRESS | System Mac Address |
| Accept | application/json | application/json |
| X-PrivateKey | api_key | API KEY generated by SmartAPI app |
| X-UserType | USER | Must be USER |
| X-SourceID | WEB | Must be WEB |
| Authorization | Bearer eyJhbGciOi... | JWT token, used in all APIs except loginByPassword. Always starts with "Bearer " |

Also commonly sent (seen in code samples throughout): `X-ClientLocalIP`, `X-ClientPublicIP` (client's local/public IP).

### Authentication with Angel (Login Services)
Requires client code, valid PIN, and TOTP. Session established via SmartAPI remains active till 12 midnight, unless user logs out.

Login Request:
```json
{
  "clientcode": "Your_client_code",
  "password": "Your_pin",
  "totp": "enter_the_code_displayed_on_your_authenticator_app",
  "state": "state_or_environment_variable"
}
```
Note: `state` is optional, echoed back in response (in request body or publisher-login query param).

Login Response:
```json
{
  "status": true,
  "message": "SUCCESS",
  "errorcode": "",
  "data": {
    "jwtToken": "eyJhbGciOiJIUzUxMiJ9...",
    "refreshToken": "eyJhbGciOiJIUzUxMiJ9...",
    "feedToken": "eyJhbGciOiJIUzUxMiJ9...",
    "state": "live"
  }
}
```
Best practice: logout every day after activity.

loginByPassword headers (no Authorization needed): Content-Type, Accept, X-UserType, X-SourceID, X-ClientLocalIP, X-ClientPublicIP, X-MACAddress, X-PrivateKey.

## Orders

Supports NORMAL, AMO (after-market, auto-detected outside market hours), STOPLOSS, ROBO (bracket) orders.
Static-IP API keys: source IP of Place/Modify/Cancel order requests validated against registered static IP.
To execute cash orders for scrips under surveillance, set `"scripconsent":"yes"`.
Market orders are converted to limit orders by AngelOne per MPP (Market Price Protection) limits.
IOC orders not allowed for commodities segment.

| Method | API | Endpoint | Description |
|---|---|---|---|
| POST | Place Order | `/rest/secure/angelbroking/order/v1/placeOrder` | Place an order |
| POST | Modify Order | `/rest/secure/angelbroking/order/v1/modifyOrder` | Modify an order |
| POST | Cancel Order | `/rest/secure/angelbroking/order/v1/cancelOrder` | Cancel an order |

## EDIS API (CDSL e-DIS authorization for selling holdings, POA-less accounts)

Needed once per day before selling holdings if user hasn't submitted Power of Attorney (POA).

| Method | API | Endpoint |
|---|---|---|
| POST | Verify DIS | `/rest/secure/angelbroking/edis/v1/verifyDis` |
| POST | Generate TPIN | `/rest/secure/angelbroking/edis/v1/generateTPIN` |
| POST | Get Transaction Status | `/rest/secure/angelbroking/edis/v1/getTranStatus` |

### Verify DIS
Request: `{ "isin": "INE528G01035", "quantity": "1" }`
Success response `data`: `ReqId`, `ReturnURL` (`https://trade.angelbroking.com/cdslpoa/response`), `DPId`, `BOID`, `TransDtls` (opaque signed blob), `version`.
If already registered today: `status:false`, errorcode `AG1000`, message "You have alreday been registered with CDSL for today."
Generic error: errorcode `AG2001`.

### Generate TPIN flow
After Verify DIS, build an auto-submitting HTML form POSTing `DPId`, `ReqId`, `Version`, `TransDtls` (values from the Verify DIS response) to `https://edis.cdslindia.com/eDIS/VerifyDIS/` — this opens the CDSL site in a browser window for the user to enter/verify their TPIN. Purely a client-side redirect page, not a JSON API call.
`generateTPIN` endpoint itself takes `{ dpId, ReqId, boid, pan }`.

### Get Transaction Status
Request: `{ "ReqId": "..." }` (ReqId from Verify DIS response)
Response `data.TransResDtls`: `ReqId`, `ReqType`, `ResId`, `ResStatus`, `ResTime`, `ResError`, `Remarks`, `RecordResDtls` (array of `{ TxnReqId, TxnId, Status, Errorcode }`).
`Status` (in RecordResDtls): `0` = not authorised to sell, `1` = authorised to sell.

## Postback / Webhook

Real-time order status updates pushed to a URL configured on the API Key (Postback URL field when creating the app). One URL per API key; all orders placed with that key trigger updates to it.

Payload shape matches an order-book item: `variety`, `ordertype`, `producttype`, `duration`, `price`, `triggerprice`, `quantity`, `disclosedquantity`, `squareoff`, `stoploss`, `trailingstoploss`, `tradingsymbol`, `transactiontype`, `exchange`, `symboltoken`, `ordertag`, `instrumenttype`, `strikeprice`, `optiontype`, `expirydate`, `lotsize`, `cancelsize`, `averageprice`, `filledshares`, `unfilledshares`, `orderid`, `text`, `status`, `orderstatus`, `updatetime`, `exchtime`, `exchorderupdatetime`, `fillid`, `filltime`, `parentorderid`, `clientcode`.

Notes:
- Only delivered over HTTPS port 443.
- AMO orders: postback not sent immediately after placing off-hours; sent at 9:00 AM when order is forwarded to exchange.
- Status values include: open, pending, executed, cancelled, partially executed, etc.

## Margin Calculator

`POST /rest/secure/angelbroking/margin/v1/batch`
Rate limit: **10 requests/second**. Max **50 positions** per request.

Request:
```json
{
  "positions": [
    { "exchange": "NFO", "qty": 50, "price": 0, "productType": "INTRADAY", "token": "67300", "tradeType": "BUY", "orderType": "LIMIT" },
    { "exchange": "NFO", "qty": 50, "price": 0, "productType": "INTRADAY", "token": "67308", "tradeType": "SELL", "orderType": "MARKET" }
  ]
}
```
Field enums: `exchange` (BSE/NSE/NFO/MCX/BFO), `producttype`/`productType` (DELIVERY/CARRYFORWARD/MARGIN/INTRADAY/BO), `tradetype`/`tradeType` (BUY/SELL), `ordertype`/`orderType` (LIMIT default/MARKET/STOPLOSS_LIMIT/STOPLOSS_MARKET). Note: for NFO, `qty` = number of units in a lot.

Response: `data.totalMarginRequired`, `data.marginComponents` = `{ netPremium, spanMargin, marginBenefit, deliveryMargin, nonNFOMargin, totOptionsPremium }`.

**Verified against a live account (2026-09-07):** margin benefit for hedged structures is smaller than you might expect. A hedged iron condor (buy both wings + sell both shorts, wings submitted first) still needed Rs.40k-95k+ margin per lot on every liquid NIFTY/BANKNIFTY/stock-option name checked - nowhere near capital-efficient for small accounts. A vertical DEBIT SPREAD (buy near strike + sell far strike, same direction) was tested too and came back needing MORE margin (~Rs.32.7k, suspiciously near-identical across two very different underlyings) than just buying the near-strike leg alone (which needs ≈ its own premium, no margin drag) - the calculator does not appear to net a simple 2-leg vertical spread's capped risk the way real exchanges typically do. If capital efficiency matters, test the exact leg combination live before assuming a "spread" or "hedge" gets margin relief.

## Market Data API (Live Quotes)

`POST /rest/secure/angelbroking/market/v1/quote/`
All exchanges supported. **Up to 50 symbols per request, rate limit 1 request/second.**

Modes: `LTP` (last traded price only), `OHLC` (open/high/low/close), `FULL` (comprehensive — LTP, OHLC, last trade qty, feed/trade time, net/percent change, avg price, volume, OI, circuit limits, buy/sell qty, 52wk hi/lo, 5-level market depth).

Request:
```json
{ "mode": "FULL", "exchangeTokens": { "NSE": ["3045","881"], "NFO": ["58662"] } }
```

Response (`data.fetched[]`, `data.unfetched[]`):
FULL mode fields: `exchange`, `tradingSymbol`, `symbolToken`, `ltp`, `open`, `high`, `low`, `close`, `lastTradeQty`, `exchFeedTime`, `exchTradeTime`, `netChange`, `percentChange`, `avgPrice`, `tradeVolume`, `opnInterest`, `lowerCircuit`, `upperCircuit`, `totBuyQuan`, `totSellQuan`, `referenceLimitPoint`, `52WeekLow`, `52WeekHigh`, `depth.buy[]`/`depth.sell[]` (each `{price, quantity, orders}`, 5 levels).
OHLC mode: `exchange`, `tradingSymbol`, `symbolToken`, `ltp`, `open`, `high`, `low`, `close`.
LTP mode: `exchange`, `tradingSymbol`, `symbolToken`, `ltp`.
`unfetched[]` items: `{ exchange, symbolToken, message, errorCode }` (e.g. `AB4018` "Symbol token cannot be empty").
`exchange` enum for this API: NSE, NFO, BSE, MCX, CDS, NCDEX. **This list is incomplete** - verified live 2026-09-09, `BFO` (BSE F&O, e.g. SENSEX options) works fine on this endpoint (FULL mode, real depth/OI/volume returned) despite not being listed here.

## Top Gainers/Losers, PCR, OI Buildup

NSE only, derivatives segment. Three sub-APIs.

**Verified against a live account (2026-09-07), not documented anywhere above:** `gainersLosers` and `OIBuildup` are rate-limited to roughly **1 request/second** - calling the 4 `OIBuildup` datatypes back-to-back gets HTTP 403 `"Access denied because of exceeding access rate"` (plain text, not JSON) on most calls. Pace calls ~1.2s apart. Also: `OIBuildup`'s response is a **top-10-per-category "movers" list**, not a per-symbol lookup - confirmed live that NIFTY/BANKNIFTY never appear in any of its 4 categories, only stock futures do. Don't rely on it for index direction signals.

### 1. Top Gainers/Losers
`POST /rest/secure/angelbroking/marketData/v1/gainersLosers`
Request: `{ "datatype": "PercOIGainers", "expirytype": "NEAR" }`
- `datatype`: PercPriceGainers, PercPriceLosers, PercOILosers, PercOIGainers
- `expirytype`: NEAR (current month), NEXT (next month), FAR (month after next)

Response `data[]`: `tradingSymbol`, `percentChange`, `symbolToken`, `opnInterest`, `netChangeOpnInterest`. Note: OI is cumulative across all strikes for that expiry, mapped to the futures contract token/symbol of that underlying+expiry (not per-strike).

### 2. PCR (Put-Call Ratio) Volume API
`GET /rest/secure/angelbroking/marketData/v1/putCallRatio` — no request body.
Response `data[]`: `pcr`, `tradingSymbol` (mapped to futures contract per underlying).

### 3. OI Buildup
`POST /rest/secure/angelbroking/marketData/v1/OIBuildup`
Request: `{ "expirytype": "NEAR", "datatype": "Long Built Up" }`
- `datatype`: "Long Built Up", "Short Built Up", "Short Covering", "Long Unwinding" (note: single spaces, exact casing matters)
- `expirytype`: NEAR, FAR, NEXT

Response `data[]`: `symbolToken`, `ltp`, `netChange`, `percentChange`, `opnInterest`, `netChangeOpnInterest`, `tradingSymbol`.

## WebSocket Streaming 2.0 (Market Data)

**URL:** `wss://smartapisocket.angelone.in/smart-stream`

### Features
- Request is JSON; response is **binary**, Little Endian byte order.
- Up to **3 concurrent WebSocket connections per client code**.
- No reconnect needed to subscribe/unsubscribe — reuse the open connection.
- A failed subscribe doesn't affect existing subscriptions. Unsub for a non-subscribed token is ignored gracefully.
- **Quota: 1000 token subscriptions per WebSocket session.** Each (token, mode) pair counts as 1 — e.g. subscribing Infosys NSE to LTP+Quote+SnapQuote = 3 subscriptions.
- Duplicate (token, mode) subscriptions are ignored, don't count against quota.
- One tick is published per (token, mode) combination — recommendation: subscribe to only one mode per token at a time.

### Auth — Request Headers (for native WebSocket clients)
| Header | Mandatory | Description |
|---|---|---|
| Authorization | Yes | JWT auth token from Login API (presumably `Bearer <jwtToken>`) |
| x-api-key | Yes | API key |
| x-client-code | Yes | Client code (Angel One trading account id) |
| x-feed-token | Yes | feed token from Login API |

### Auth — Browser-based clients
Append query params instead of headers:
```
wss://smartapisocket.angelone.in/smart-stream?clientCode=&feedToken=&apiKey=
```
(`clientCode`, `feedToken`, `apiKey` all mandatory.) Error handling/status codes are the same either way.

### Auth error response headers
On HTTP 401, `x-error-message` header contains one of: "Invalid Header - Invalid Auth token", "Invalid Header - Invalid Client Code", "Invalid Header - Invalid API Key", "Invalid Header - Invalid Feed Token".

### Heartbeat
Client must send text `ping` every 30 seconds to keep the connection alive. Server replies with text `pong`.

### Subscribe/Unsubscribe Request (JSON, text frame)
```json
{
  "correlationID": "abcde12345",
  "action": 1,
  "params": {
    "mode": 1,
    "tokenList": [
      { "exchangeType": 1, "tokens": ["10626", "5290"] },
      { "exchangeType": 5, "tokens": ["234230", "234235", "234219"] }
    ]
  }
}
```
- `correlationID` (string, optional): up to 10-char alphanumeric ID, echoed back in error responses for request tracking.
- `action` (int, mandatory): `1` = Subscribe, `0` = Unsubscribe.
- `params.mode` (int, mandatory): `1` = LTP, `2` = Quote, `3` = Snap Quote.
- `params.tokenList[]` (mandatory): array of `{ exchangeType, tokens[] }`.
- `exchangeType` enum: `1` = nse_cm, `2` = nse_fo, `3` = bse_cm, `4` = bse_fo, `5` = mcx_fo. (Tokens come from the Instrument/Scrip Master.)

### Scrip Master dump
Array of objects: `{ "token", "symbol", "name", "expiry", "strike", "lotsize", "instrumenttype", "exch_seg", "tick_size", "freeze_qty", "is_cas_enabled" }`.
This is the master file to resolve `tradingsymbol` ↔ `symboltoken` ↔ `exch_seg` for all REST/WebSocket calls — download and cache/refresh daily.

**Verified against a live download (2026-09-07), correcting this doc page's own text:** `exch_seg` is a plain exchange code — `NSE`, `NFO`, `BSE`, `BFO`, `MCX`, `CDS`, `NCDEX`, `NCO` — NOT the "nse_cm"/"nse_fo" naming (that belongs to the WebSocket `exchangeType` field only, see WebSocket Streaming 2.0 above). `strike` is the actual strike price × 100. `freeze_qty` is present per row — NSE's per-order max quantity for that contract; larger orders must be split. Index spot instruments (for LTP lookups) have `instrumenttype: "AMXIDX"`, e.g. NIFTY → token `99926000`, BANKNIFTY → token `99926009`, both `exch_seg: "NSE"`. Equity spot rows have `instrumenttype: ""` with tradingsymbol ending `-EQ`. Options: `instrumenttype` is `OPTIDX` (index) or `OPTSTK` (stock), `exch_seg` is `NFO`/`BFO`, `expiry` format is `DDMMMYYYY` (e.g. `08SEP2026`), tradingsymbol ends `CE`/`PE`. As of this date, NIFTY has weekly expiries; BANKNIFTY and stock options are monthly only.

**SENSEX verified live 2026-09-09** (a BSE index, not NSE): spot is `instrumenttype: "AMXIDX"`, `exch_seg: "BSE"`, token `99919000` - a different exchange from every other index checked so far. Its options are `exch_seg: "BFO"` (not `NFO`), `instrumenttype: "OPTIDX"`, lotsize `20`, freeze_qty `1000`, and - unlike BANKNIFTY/stocks - **SENSEX has weekly expiries** (confirmed: 2026-09-10, 09-17, 09-24, 10-01, 10-08 all listed simultaneously), closer to NIFTY's cadence than BANKNIFTY's monthly-only one.

CSV-flavored column doc (same data, alt framing): `exchange_token`, `tradingsymbol`, `name`, `expiry`, `strike`, `tick_size`, `lot_size`, `instrument_type` (EQ, FUT, CE, PE).

### searchScrip
Request: `{ "exchange": "NSE", "searchscrip": "SBIN" }`
Response `data[]`: `{ exchange, tradingsymbol, symboltoken }` — returns all matching series (EQ, BE, BL, etc.), only one exchange/search term per request.

### nseIntraday / bseIntraday
